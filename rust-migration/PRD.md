# PRD — Mantishack Python → Rust Rewrite

**Status:** active · **Owner:** migration orchestrator · **Driver:** `rust-migration/orchestrator/migrate.py`

---

## 1. Problem & goal

Mantishack is **~438K LOC of Python** across **1,662 modules / 210 packages** (≈227K LOC
of first-party source; the rest is tests/fixtures). The goal is to **rewrite the code in
Rust** — faithfully, package by package, with **zero behavior change** — so the
CPU-bound analysis core runs at native speed while the LLM/agentic orchestration that
has no Rust equivalent stays in Python and calls *into* the Rust crates.

This is **a rewrite, not a redesign.** Every ported package must produce byte-identical
results to the Python it replaces, proven by the original test suite.

## 2. Why incremental, not big-bang

A single 438K-LOC rewrite cannot be held in one context window, cannot be reviewed,
and cannot be verified. The orchestrator therefore decomposes the work into
**independently shippable package ports**, each:

- run in a **fresh, scoped Claude Code context** (only that package's files),
- verified against the **Python test suite as a parity oracle**,
- committed atomically per phase.

State lives on disk (`migration-state.json`), never in conversation memory, so any
machine or session can resume the migration deterministically.

## 3. Scope & dispositions

Every package is classified (`orchestrator/inventory.py`) into one disposition:

| Disposition  | Meaning                                                        | Packages | LOC      |
|--------------|---------------------------------------------------------------|---------:|---------:|
| `rust-port`  | Pure compute — port to a Rust crate                           |       30 |   74,507 |
| `rust-glue`  | Wraps an external binary — port the glue, keep the binary     |       28 |   81,377 |
| `keep-python`| LLM/agentic/SDK-bound — stays Python, calls into Rust         |       17 |   26,870 |
| `review`     | Ambiguous — a human dispositions it                           |       36 |   44,348 |
| `skip-test`  | Test/fixture package — becomes the parity oracle, not ported  |       99 |  211,460 |

**In scope for Rust:** `rust-port` + `rust-glue` (58 packages, ~156K LOC).
**Out of scope:** `keep-python` (the AI orchestration moat), `skip-test`.
**Gated:** `review` packages block until a human assigns a disposition.

## 4. Non-negotiable requirements

| # | Requirement                                                                          |
|---|--------------------------------------------------------------------------------------|
| R1| **Behavioral parity.** Same inputs → same outputs, incl. edge cases, errors, rounding.|
| R2| **No API changes.** Python callers switch by changing one import line.               |
| R3| **PyO3 bindings.** Each crate exposes the original public symbols.                    |
| R4| **Bounded context.** A port task sees only its package's files + already-ported deps. |
| R5| **Parity-gated commits.** A package commits only after `verify.py` is green.          |
| R6| **Atomic phase commits.** One tidy, attributed commit per phase.                      |
| R7| **Dependency order.** A package is ported only after every internal dep is resolved.  |
| R8| **Idempotent & resumable.** Re-running skips done work; state is on disk.             |

## 5. Architecture

```
rust-migration/
├── PRD.md                       ← this file
├── PHASES.md                    ← phase definitions + context operations
├── migration-manifest.json      ← inventory + classification + port order (generated)
├── migration-state.json         ← durable per-package status ledger (generated)
├── PHASES.lock.json             ← package→phase assignment (generated by `migrate plan`)
├── Cargo.toml                   ← Rust workspace (members grow as packages port)
├── orchestrator/
│   ├── inventory.py   ← AST scan → classify → topo-order  → manifest
│   ├── state.py       ← durable status ledger (pending→…→verified→wired)
│   ├── context.py     ← per-package context bundle generator (the clean-context op)
│   ├── verify.py      ← parity gate: cargo test + Python oracle under Rust backend
│   └── migrate.py     ← driver: plan / bundle / port / run / commit
├── phases/phaseN/<pkg>.task.md  ← generated faithful-rewrite task bundles
└── crates/<crate>/              ← the Rust crates (one per ported package)
```

The Rust↔Python seam: each ported crate ships a thin shim re-exporting its PyO3
symbols under the original module names. The package `__init__` imports the Rust
shim when `MANTISHACK_USE_RUST=1`, else the legacy Python — enabling A/B parity
runs and a reversible cutover.

## 6. Success metrics

- **Correctness:** 100% of each ported package's Python tests pass under the Rust backend.
- **Coverage:** `rust-port` + `rust-glue` packages reach `verified` (target: 58/58).
- **Performance:** call-graph / reachability hot paths ≥10× faster (tracked, not gating).
- **Safety:** no `unsafe` outside explicitly justified spots; `cargo clippy` clean.

## 7. Risks & mitigations

| Risk                                            | Mitigation                                              |
|-------------------------------------------------|---------------------------------------------------------|
| Context drift on large packages                 | One package per task; files-in-scope hard-listed (R4).  |
| Silent behavior change                          | Python test suite is the oracle; parity-gated (R1,R5).  |
| Float / rounding divergence                     | Golden vectors generated from Python, baked into tests. |
| `review` packages stall the pipeline            | They're isolated; Rust phases proceed without them.     |
| External-tool version skew (codeql/semgrep)     | `rust-glue` keeps the binary; only the glue is ported.  |

## 8. Out of scope

Reimplementing CodeQL/Semgrep/AFL++/Coccinelle/Z3 themselves; rewriting the LLM
provider layer or agentic orchestration; any feature work. This migration changes
the *implementation language of the compute core only*.
